# Managed Maven build implementation

Approved intent: Build and Run / Build and Debug generate a derived POM, include declared provided dependencies for a standalone local WAR, use managed Maven/JDK, and deploy only after a successful build. Original application POM and normal build output remain untouched.

1. Add optional per-instance build configuration and managed pinned Maven 3.9.16 provisioning using official ZIP/SHA-512 and existing cache/leases.
2. Generate a temporary POM next to the selected original POM to preserve relative parents/resources. Support one WAR module, preserve repositories/profiles/properties, isolate output beneath .tomcat-workbench/<instance>/build, inject provided dependency staging and WAR resources with container/tool exclusions and optional extra dependencies.
3. Invoke Maven through managed Java/ClassWorlds with arguments (no cmd interpolation), cancellation and output capture. Clean only the verified isolated output using extension code rather than executing inherited Maven clean filesets. Snapshot the successful WAR under artifacts, preserve the last successful artifact on failures, and remove the owned temporary POM.
4. Add Build WAR, Preview Build POM, Build and Run and Build and Debug commands. Build before touching running Tomcat, publish the resulting artifact to the configured context, then start normally or attach managed debug. Preserve explicit server libraries/configuration; document migration of earlier legacy shared-library workarounds.
5. Verify transformed POM behavior and failure/cancellation paths, actual managed Maven builds including provided JAR/container exclusions, artifact deployment, existing lifecycle/debug suites, documentation and VSIX 0.4.0.

Defaults: pom.xml, instance context chosen once, Maven 3.9.16, includeProvided=true, skipTests=false, goal=package. Optional profiles, project-local settings, extra dependencies and exclusions. install is opt-in and writes the derived artifact/POM to the local Maven repository. Multi-module roots and non-WAR packaging report a diagnostic. Missing undeclared runtime dependencies are explicit overrides, never guessed from a class name. No changes to the corporate application's source/POM or live server during extension implementation/testing.

Implementation decisions and review fixes: resolve Help Plugin effective POM first, flatten parent/profiles only after resolution, remap conventional build output including profile/execution paths, and filter container JARs from the final WAR as well as provided staging. Leases key the canonical project/instance output rather than the chosen module path; Maven/root-child PIDs protect leases after host failure. Cancellation captures and terminates the Windows process tree and active builds are awaited during deactivation. ExcludeProvidedGroups intentionally applies only to added provided staging; excludeArtifacts and default container API patterns apply to the final WAR. Log4j2 selection uses actual dependencies rather than unused BOM entries.

Verification: local suite 51/51 passed, including output-lock changes, cancellation of a real forked process, inherited/profile paths, production WAR exclusions and preservation of successful snapshots. Live managed Maven 3.9.16/Java 8 built a fixture WAR, included provided/extra libraries, excluded compile-scope embedded Tomcat, preserved original POM/target, served the application through managed Tomcat, and preserved the running deployment after a compilation failure. The debug/JDI and four-family lifecycle integrations also passed. A transient dying-process CIM metadata race was observed and process identity now retries/read-checks conservatively before reporting ownership failure.

Corporate project configuration migration: added build.pom/context and the explicit missing HttpClient override to the user's sisdoated-rs instance; removed only the earlier shared-library workaround entries, retained PostgreSQL for JNDI, restored the default loader and backed up the two configuration files. Original application POM/WAR/source and running server were not changed or executed. Corporate application startup has not been validated by the extension's fixture tests.
